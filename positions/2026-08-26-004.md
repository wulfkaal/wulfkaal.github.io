# kaal:position:2026-08-26-004

**Affirmed position.** Offline capability is an architectural test, not a feature label. Kleppmann and coauthors distinguish cloud applications from local-first software by the location of the primary data copy, the presence of a locally installed executable, and continued operation without a network connection. Their prototypes permit users to disconnect, continue working, and later merge changes. Applications centered on synchronous server interaction instead lock users out when the network fails. This independently extends Kaal's operational test: retained function under isolation supplies observable evidence that computation and state remain on the user's device.

The correspondence has limits. Local-first software addresses collaborative data applications, not agent runtimes or model inference. Offline editing does not establish that every relevant computation occurs locally, and later synchronization may still depend on external infrastructure. The paper nevertheless sharpens the classification rule. A local interface cannot establish local execution when the underlying capability disappears at disconnection. Network isolation converts an architectural claim into a falsifiable test.
