**Affirmed position.** Code establishes a model's implementation. Economic effects require separate evidence. Gräbner's validation framework explains the distinction. Model verification tests whether a computational model does what its designer intended. Validation asks whether the model reasonably represents its target and assesses the model's relationship to reality. His framework also requires an explicit key between model properties and target-system properties. Validation becomes necessary when the model is used to make informed statements about the real world.

This independently qualifies Kaal's claim. Formal objects and source code can make a mechanism explicit and testable. They do not show that the named economic effect occurred. That inference requires observable target properties and an appropriate validation design.

The source concerns computational models generally. The analysis does not evaluate Kaal's framework, observables, code, or evidence. It supplies a methodological boundary. No economic effect follows from that boundary.
